# ADR 0012: 音声刺激の研究実施規則を固定する

- 状態: 承認（研究用刺激標準化）
- 決定日: 2026-08-12
- 音声実施規則ID: `audio-options-offline-mp3-ordered-once-v1`
- 妥当化状態: `research-stimulus-standardized-not-mode-valid`
- 対象: 音声版の研究データ収集

## 決定

音声版を次の手続へ固定する。

- 問題語は日本語テキストとして視覚提示し、問題語音声は提示しない。
- 英語4選択肢の綴りは画面とアクセシビリティtreeの双方から除外し、同梱MP3だけを提示する。回答ボタンはA–Dのlabelだけを公開する。
- 選択肢音声はA、B、C、Dの順に各1回、再生終了まで聞く。4件すべての完了前は回答ボタンを無効にする。
- 正常完了した音声は再生できない。読み込み・再生失敗時だけ同じ選択肢を再試行できる。
- 15秒以内に再生完了またはブラウザの終了通知が得られなければ失敗として扱い、同じ選択肢の再試行を許す。
- 同時再生と端末のWeb Speech APIによるTTS fallbackを禁止する。欠損音声を端末固有の声へ置換しない。
- 選択肢順は研究実施seed、項目index、問題番号から `fnv1a32-domain-audio-options-v1` でseedを導出し、`mulberry32-v1` Fisher–Yatesで再現可能にする。
- Excelへ実施規則、資産manifest、選択肢順seed導出法、再生回数、失敗回数を保存する。

この決定は、筆記項目パラメータが音声条件で妥当であることを意味しない。潜在得点default-denyと `audio-mode-requires-independent-calibration` を維持する。

## 修正した不具合

項目バンクは日本語の問題語と英語4選択肢を持つ。一方、同梱音声639件は英語選択肢の語形にだけ対応する。旧画面は日本語問題語にも英語音声用pathを生成していたため、資産取得に失敗し、英語設定の端末TTSへ日本語を渡していた。さらにWeb Speech APIの利用可能voiceはOS・ブラウザ・設定に依存する。

この経路は刺激の内容と音声特性を参加者間で固定できず、音声不在を無言で別方式へ置換する。したがって研究実施経路から除去した。

## 音声資産契約

- 項目バンク: 160項目 × 英語4選択肢 = 640セル、重複を除く639語。
- 資産: `public/audio/*.mp3` 639件。欠損0、余剰0、slug衝突0。
- 各ファイルの先頭frame: MPEG-2 Layer III、64 kbps、24 kHz、mono。
- manifest ID: `vst-nj8-audio-options-v1`。
- manifest SHA-256: `f610cbf2c60a02ec6d3012c8c5827acdc0937bf3572b1c3e6bb6a6943a060772`。
- manifest算出法: filename昇順に `sha256(file bytes) + two spaces + basename + LF` をUTF-8で連結し、その全体をSHA-256化する。
- 既存生成scriptは `gTTS(text, lang="en", slow=False)` を示す。しかし生成時のgTTS version、voice/backend identity、ネットワークサービスのrevisionは履歴に保存されていない。この情報欠損を推測で補わず、`unrecorded`として結果へ保存する。

資産は既存音声をfreezeしたものであり、発音の言語学的適切性、語義との整合、アクセント、音量正規化、無音時間、機器上の知覚品質を承認したものではない。

## 機械的強制

- `src/utils/audioAdministrationPolicy.ts` に提示手続と監査項目を閉じる。
- 状態遷移テストがA→B→C→D、完了前回答禁止、成功後再生禁止、失敗後再試行を検査する。
- 選択肢順のseed導出と固定fixtureを検査する。
- `scripts/verify-audio-administration.ts` が640セルと639資産の全単射、全ファイルhash、MP3 frame header、実アプリのTTS・問題語音声不在を検査する。
- `npm run check` で上記検証を必須化する。

## 残る本質的ゲート

1. 内容専門家または音声学的レビューによる639刺激の発音・語義・音質監査。
2. 音量・duration・leading/trailing silenceを定量化し、外れ値を事前規則で処理するQA計画。
3. ヘッドホン、騒音、音量、端末・ブラウザ、聴力、再生障害を含む実施環境仕様。
4. 音声条件での独立項目校正、適合、局所依存、DIF、筆記版とのモード等価性または得点リンク。
5. 同一MP3資産を版付き再現パッケージとして保存できる長期配布方法。

これらを満たすまで、音声版は研究用応答ログ収集に限り、語彙サイズ得点を公開しない。

## 帰結

- 選択肢を自由な順序・回数で聞く旧データと本規則のデータは、同じ音声実施条件として無条件に併合しない。
- 音声エラー時は回答不能のまま明示し、TTSで代替して継続しない。
- 別の再生回数、順序、話者、速度、資産へ変更する場合は新しい音声実施規則IDとmanifestを発行する。
